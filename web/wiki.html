Guides

Every guide here ends at a working result — a page in your browser, or the admin screen of whatever you installed. If you got that far, you are done; the rest is your project, not the server.

Install and first launch

  1. Download the build for your macOS from the main page and drag ServerMaster.app into Applications.
  2. First launch needs a right-click. The app is not notarized yet, so a double-click will be refused. Right-click the app → Open → Open again. You do this once, ever.
  3. On the Dependencies screen, press Install next to anything the engine you want is missing. This uses Homebrew and takes a few minutes the first time.
Nothing is bundled and hidden. ServerMaster runs the real Nginx, PHP and MariaDB, each in its own folder on its own port. A MySQL or Apache you already have is left alone, and uninstalling is dragging the app to the Trash.

A static site

HTML, CSS and JavaScript in a folder. The fastest thing this app does.

  1. Profiles → + to create a profile.
  2. Set Root to your folder — the one containing index.html.
  3. Leave the engine at http-server and the port at 8080.
  4. Control → Start, then click the address.
Done when your page opens at http://127.0.0.1:8080.

If your site is a single-page app that handles its own routes, switch on SPA fallback in the profile so a deep link does not 404.

A PHP project

Any folder with .php files in it, no database needed.

  1. New profile, Root at the folder with index.php.
  2. Engine: PHP built-in server for something simple, or PHP site (Nginx + PHP-FPM) for anything real.
  3. Start, and open the address.
Done when the page shows the output of your script instead of its source code.
Seeing PHP source in the browser means the engine is not executing PHP — you picked a static engine. Switch to a PHP one. ServerMaster warns about this before you start.

Joomla

The full path: database, install, admin panel.

  1. Download Joomla and unpack it into a folder of its own.
  2. Database → Start. Then create a database — give it a name, a user and a password, and press Create.
  3. New profile. Root at the Joomla folder. Engine: PHP site (Apache + PHP-FPM) — Joomla ships its own .htaccess and Apache honours it.
  4. Start, open the address. Joomla's installer appears.
  5. When it asks for the database, copy the details from the Database screen: host 127.0.0.1:3307, and the name, user and password you just made.
  6. Finish the installer and delete the installation folder when it asks.
Done when you can sign in at /administrator.

For clean URLs: rename htaccess.txt to .htaccess in the Joomla folder, then turn on SEF URLs with URL rewriting in Joomla's global configuration. On the Apache engine this works with no further setup.

WordPress

  1. Unpack WordPress into its own folder.
  2. Database → Start → create a database.
  3. New profile, root at the WordPress folder, engine PHP site (Nginx + PHP-FPM) — or the Apache one if you plan to use permalink rules from a plugin.
  4. Start, open the address, follow the installer with the database details from the Database screen.
Done when /wp-admin lets you in.

Drupal

Same shape as the others, with one trap: in a Composer-built Drupal the site root is the web subfolder, not the project folder. Point Root at …/web. ServerMaster spots this and warns you before starting.

Done when the installer finishes and /user/login works.

Laravel

Same trap, different name: point Root at the public folder. Use a PHP engine, and create a database first if the project needs one — then fill in .env with the details from the Database screen.

Done when the Laravel welcome page appears.

The database

Database → Start brings up a MariaDB that belongs to ServerMaster alone: its own data folder, its own port 3307. It does not touch a MySQL you already have.

Press Start and open under Web admin panel and a full database interface opens in your browser, already signed in. Choose between Adminer and phpMyAdmin in Settings — Adminer comes with the app, phpMyAdmin installs through Homebrew.

Done when the panel lists your databases in the browser.
The panel listens on 127.0.0.1 only. It is unrestricted access to every database on that instance, so it is deliberately not reachable from your network.

PHP version per project

An old project needing PHP 8.3 and a new one on 8.5 can run at the same time. The version belongs to the profile, not to your machine.

  1. Install the version you need: brew install php@8.3.
  2. In the profile, pick it under PHP version.
  3. Start. The site runs on that version, whatever the rest of the system uses.

HTTPS

Switch on HTTPS in the profile and press Certificates… to generate one. The site then opens over https://.

A self-signed certificate makes the browser warn you — the encryption is real, but nothing vouches for the certificate. Two ways out, both asking for your password once: press Trust in the system in the certificates window, or install mkcert (brew install mkcert) and let ServerMaster use its local authority, which browsers accept silently.

Ports 80 and 443

Ports below 1024 belong to root — being an admin is not enough. Switch on Administrator rights in the profile and macOS will ask for your password once, in its own window. ServerMaster never sees it, and stopping the server later needs no password at all.

You usually do not need this. 8080 instead of 80, and 8443 instead of 443, behave identically for local work.

When you need .htaccess

Only Apache reads .htaccess. If your project ships one — with rewrite rules, redirects, access control or headers — pick Apache or PHP site (Apache + PHP-FPM) and it will be honoured as it was under XAMPP or MAMP. Nothing to install: macOS already carries Apache.

Nginx does not read those files. Common CMS clean URLs still work there, because ServerMaster writes the equivalent rule into the generated config — but anything custom in your .htaccess will be ignored.

Errors and what they mean

Port 8080 is taken

Something else is already listening. Open Ports, find what holds it, and stop it from there — or just change the port in the profile.

listen EACCES: permission denied

You picked a port below 1024. Either switch on Administrator rights in the profile, or move to 8080 / 8443.

The page is blank

Usually a PHP error. Open Console and look at that profile's log — PHP errors are written there rather than swallowed. In the profile's file list, php-error.log is the one to read.

The browser shows PHP source instead of the page

The engine does not execute PHP. Switch to a PHP engine. This is worth fixing at once: the source of configuration.php or wp-config.php contains your database password.

Your connection is not private

The self-signed certificate is not trusted. See HTTPS — either trust it in the system or switch to mkcert.

404 on every page except the front one

Clean URLs are on but nothing is rewriting them. On Apache, make sure the project's .htaccess exists — Joomla ships it as htaccess.txt and it has to be renamed. On Nginx, custom rules from an .htaccess are not read at all; see when you need .htaccess.

The CMS installer cannot connect to the database

Check three things: the database is started on the Database screen, the host is 127.0.0.1:3307 and not localhost, and the user and password are the ones you created there.

Adminer: No such file or directory

The Server field is at localhost, which makes it look for a socket that is not there. Use 127.0.0.1:3307. Opening the panel with the button fills this in for you.

The CMS cannot write files or install extensions

File permissions. The profile editor has a permissions check that finds the folders your CMS needs to write to and fixes them.

“ServerMaster” cannot be opened

Gatekeeper on first launch, because the build is not notarized yet. Right-click the app → Open → Open. Once is enough.

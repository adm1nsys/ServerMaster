# macOS ↔ Windows parity checklist

This is a release checklist, not a promise that two different operating systems
will expose identical system tools. PowerShell/CMD are intentionally excluded:
they are Windows-only. Likewise, macOS keeps its native terminal, widget and
Safari-extension integration instead of imitating the Windows tray UI.

## Shared product contract

- [x] Profile JSON keeps the shared fields: engine, paths, environment,
  `templateId`, `needsDatabase`, profile colour, notes and server settings.
- [x] Older macOS profile files migrate safely: a missing `profileColor` takes
  the previous error-page accent instead of resetting a profile.
- [x] Profile colours match the Windows palette and tint the currently active
  profile background independently of error-page colours.
- [x] Imported/exported template JSON keeps Windows package metadata and Node
  entry filenames (`nodeEntryFile`) without rewriting `server.cjs` to
  `server.js`.
- [x] Both editions expose the same built-in template identities, including
  Joomla 5/6, WordPress, PrintShop CRM, Web-to-Print Store and Showcase.

## Server workbench

- [x] macOS has profiles, start/stop/restart, logs, dependency management,
  database administration, port inspection, backups, diagnostics, files,
  settings, certificates and update checks.
- [x] Template profiles retain their selected colour, template identity and
  database requirement after creation and after a cross-platform import.
- [x] A Node template can use either CommonJS (`server.cjs`) or ES modules
  (`server.mjs`) instead of assuming only `server.js`.
- [x] macOS has its own native replacement for Windows-only shell/tray flows;
  no PowerShell or CMD parity is required.
- [x] Crash recovery uses the same safe policy as Windows: 1/2/4-second
  backoff, no more than three attempts in one minute, and cancellation after a
  manual stop/restart.
- [x] Ports does not claim a root-owned listener is free: when macOS hides its
  owner from ordinary `lsof`, the listener is still listed as non-killable and
  startup stops with an actionable message instead of launching into a conflict.

## Guided project setup

- [x] Joomla 5/6 downloads use an official release asset and verify GitHub's
  published SHA-256 digest before extraction.
- [x] WordPress and PrintShop CRM can be downloaded into an empty chosen folder;
  existing projects are never overwritten or merged.
- [x] Web-to-Print creates an isolated MariaDB database and local configuration,
  installs WordPress, WooCommerce and optionally Printcart, and keeps the
  folder/profile after a recoverable failure.
- [x] PrintShop CRM creates its local SQLite/upload configuration, runs npm
  install and does not fail solely because an optional seed script is absent.
- [x] The macOS Showcase seeds the same presentational store data as Windows:
  Ukrainian settings, print options, product variants, payment and example
  orders. Product artwork remains deliberately generated by each platform's
  own local runtime.
- [x] A recipe writes an on-disk `.servermaster-recipe.json` marker only after
  successful preparation; a retry reuses the database named by an existing
  WordPress configuration instead of creating another one.

## Release evidence still required on a real Mac

- [ ] Fresh Joomla 5 and Joomla 6 project: start, stop, restart and verify that
  the port is released even when Apache/PHP is launched with administrator
  rights.
- [ ] Fresh Web-to-Print Showcase: verify database creation, WooCommerce,
  Ukrainian demo data, an order, and rerun behaviour.
- [ ] Fresh PrintShop CRM: verify npm install, local SQLite data and restart.
- [ ] Export a profile on macOS and import it on Windows; repeat in the opposite
  direction with a `server.cjs` Node profile and a coloured profile.
- [ ] Run the release build and smoke-test it outside Xcode.

The final five checks cannot be honestly ticked by source review: they need a
real local runtime and network/dependency environment.
